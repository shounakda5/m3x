M3X Sprint Implementation Plan

Three-day roadmap covering data preparation, model training, and ring MCU deployment. Phases 1 → 2 → 3 are strictly sequential. Refactoring runs in parallel on Monday alongside Phase 1. Models are split by ownership: Anisha owns SVM and Random Forest; Shounak owns CNN and XGBoost and all .tflite generation; Farhad owns the MCU hardware side.

Mon Jun 2 – Thu Jun 5, 2026 Anisha — Data · SVM · Random Forest Shounak — CNN · XGBoost · .tflite (~2 hrs/day) Farhad — MCU · Arduino · Deployment Mon–Wed: Active work Thu: Tweaks & review only

1. Current State

Already built in this repo

  • Complete ML pipeline: SVM, Random Forest, XGBoost, 1D CNN
  • Stratified Group K-Fold cross-validation (5 folds, group = 10s epoch)
  • Hyperparameter tuning via tune.py — RF best at 76% acc / 0.70 F1 macro
  • Per-fold metrics, confusion matrix, classification report already output by metrics.py
  • Feature engineering: LED1/LED2 PPG, HRV, temperature, accelerometer (16 features)
  • Label classification pipeline from Qualtrics survey exports
  • Duty-cycle correction for 10s-ON / 20s-OFF sensor rhythm

Gaps this sprint must address

  • Data has only 3 of 4 stress classes — Eustress is entirely absent
  • LED3 channel not yet supported in the feature pipeline or config.py
  • Window size is hardcoded to 10s — must be parameterized for the 5-size sweep
  • No model serialization: trained models exist only in memory (no .pkl / .h5)
  • No .tflite export pipeline and no Arduino deployment code
  • Single participant, single session — limited generalizability

5 — Write scripts/export_tflite.py

Generates a .tflite file from any saved model. Run once Monday on existing models to produce POC files for Farhad. Run again Wednesday on the winning model to produce the final file.

import tensorflow as tf, joblib, sys from pathlib import Path results_dir = Path(sys.argv[1]) # e.g. results/window_10s # CNN → TFLite converter = tf.lite.TFLiteConverter.from_saved_model( str(results_dir / "cnn_model.h5") ) converter.optimizations = [tf.lite.Optimize.DEFAULT] (results_dir / "cnn_model.tflite").write_bytes(converter.convert()) # RF / XGBoost / SVM → emlearn (tree-safe, MCU-friendly) import emlearn for name in ["model"]: # adjust for each saved .pkl m = joblib.load(results_dir / f"{name}.pkl") em = emlearn.convert(m, method="inline") em.save(file=str(results_dir / f"{name}.h"), name=name)
emlearn vs TFLite Micro decision: Farhad confirms MCU RAM on Monday. If RAM < 256 KB, emlearn is the path for all tree models. CNN always uses TFLiteConverter.

6. Phase 1 — Data Preparation Gates Phase 2

Anisha owns this phase entirely. The work happens outside the repo (raw sensor recordings → labeled feature CSV) and is Anisha's full-day focus on Monday. The output drops into data/features/ and both Phase 2 training tracks begin as soon as it lands.

Deliverable

data/features/features_labeled_new.csv
Same schema as features_output_24hz.csv but with all LED3 columns added and all 4 stress classes present.

Hard requirements for the training pipeline

  • All columns in FEATURE_COLS present (NaNs acceptable — imputed downstream)
  • Label column uses exactly: relax, eustress, distress, eustress+distress
  • Window grouping column present so sub-window leakage is prevented in K-Fold CV
  • If multiple participants: a Participant_ID column is included
  • Each class has at least 50 samples
  • NaN rate per feature column is below 30%

Target class sample counts

ClassCurrentTarget minimum
Relax145 rows (17%)≥ 150
Eustress0 rows≥ 100
Distress197 rows (23%)≥ 150
Eustress + Distress519 rows (60%)≥ 150
If Eustress remains under-represented: options are (1) collect more sessions, (2) SMOTE oversampling in preprocess.py, or (3) collapse to 3-class. This must be resolved Monday — it changes the output layer of every model.
Window-size note: Fixed-rate feature extraction is preferred. Anisha extracts at a single rate; Shounak and Anisha's training scripts each aggregate rows for the appropriate window size inside preprocess.py.
