Section 01

🎯Project Overview

This pipeline was built for a study conducted at USC in which participants wore a wrist sensor while periodically answering short surveys (Ecological Momentary Assessments, or EMAs) about their psychological state. The goal is to train a classifier that can infer a participant's stress state from physiological signals alone — without needing them to fill out a survey.

Stress is modeled along two independent dimensions: Opportunity (perceived challenge or potential upside) and Pressure (perceived demand or threat). Combining these two dimensions yields four theoretically distinct states:

Pressure LOWPressure HIGH
Opportunity HIGHEustressMixed
Opportunity LOWRelaxedDistress
In this dataset, only three states are represented: Relaxed, Distress, and Mixed. No participant reported a pure Eustress state during the recording session, so the classifier is trained on three classes only.
Section 02

📡Data Sources

The pipeline draws on two independent data streams that must be carefully aligned:

Wrist Sensor Data

A wrist-worn optical sensor collected photoplethysmography (PPG), heart rate, heart rate variability, and accelerometer signals at 24 Hz. Crucially, the sensor operated on a duty cycle — 10 seconds on, 20 seconds off — to conserve battery. Signals were pre-processed externally into a feature matrix of 861 rows and 16 physiological features per row.

EMA Survey Data

Participants answered 8 surveys via Qualtrics over the course of the session. Each survey asked them to rate Opportunity and Pressure on a 6-point Likert scale (text responses such as "Slightly agree"). Survey timestamps are wall-clock times; sensor timestamps are seconds elapsed since the sensor powered on.

Key Challenge — Bridging two incompatible time systems (absolute wall-clock vs. relative elapsed seconds) is the central data engineering challenge of the pipeline.

Section 04

📋Stage 1 — Survey Label Classification

Input: Raw Qualtrics CSV export. The first two rows are Qualtrics metadata headers; the pipeline skips them and reads actual responses from the third row onward.

Label Assignment Rules

Each response contains free-text answers for Opportunity and Pressure. These are mapped to a numeric score from 1 to 6. A threshold rule then assigns the stress label:

OpportunityPressureLabel
Score 4–6 (HIGH)Score 1–3 (LOW)Eustress
Score 1–3 (LOW)Score 4–6 (HIGH)Distress
Score 1–3 (LOW)Score 1–3 (LOW)Relaxed
Score 4–6 (HIGH)Score 4–6 (HIGH)Mixed

Session Summary

8 surveys were collected over approximately 3 hours (14:33 to 17:35). Labels were: 3 × Relaxed, 1 × Distress, 3 × Mixed, 1 × Eustress.

Output: A CSV with one row per survey response, containing start/end timestamps, raw text responses, numeric scores, and the assigned label.

Section 05

⏱️Stage 2 — Label Merging and Time Alignment

This is the most technically involved stage. It resolves the mismatch between two incompatible time systems and propagates survey labels onto every sensor feature row.

5a. Time Synchronization

Survey timestamps are absolute wall-clock times (e.g., 14:33:12). Sensor timestamps are seconds elapsed since power-on. To align them, the pipeline designates the first survey's start time as t = 0 and converts all survey timestamps to seconds relative to that origin. Only the time-of-day component is used (not the date), making the script safe for multi-day sessions.

5b. Duty-Cycle Correction

Critical correction — easy to overlook. Because the sensor was off for 20 seconds of every 30-second cycle, raw feature timestamps do not reflect real elapsed time. Without correction, every sensor measurement would be placed far too early in the session timeline and matched to the wrong survey label.

The fix adds block_index × 20 seconds to every timestamp, where block index is assigned by sorting the unique window values:

Raw WindowCorrected Window
20.0 – 30.0 s40.0 – 50.0 s
30.0 – 40.0 s70.0 – 80.0 s
60.0 – 70.0 s160.0 – 170.0 s

After correction, the sensor timeline spans t = 12s to t = 8,598s, consistent with 287 recording blocks × 30 seconds per cycle = 8,610 seconds of real elapsed time.

5c. Label Propagation (Forward-Fill)

  • Feature windows within a survey's [start, end] interval → that survey's label.
  • Feature windows in the gap between surveys → the next survey's label (forward-fill).
  • Feature windows after the last survey → Unknown, excluded from training.

5d. Survey Coverage and Label Distribution

The sensor recording (8,610s) ended before the survey session concluded (10,916s). Surveys 5–8 fall outside the recording window, but their labels reach backward through the gaps.

Section 07

⚙️Preprocessing

  1. Artifact Handling: Infinite values (from division by zero in ratio features) are replaced with NaN. All remaining NaN values are imputed with the column median — a robust choice unaffected by extreme outliers from sensor noise.

  2. Feature Scaling: A StandardScaler (zero mean, unit variance) is applied to normalize features for the SVM. The scaler is fit only on the training portion of each cross-validation fold and then applied to the test portion. Fitting on the full dataset before splitting would leak test-set statistics into training — a subtle but consequential form of data leakage. The Random Forest skips scaling entirely, as tree-based models are scale-invariant.

  3. Group and Label Extraction: Index columns (window identifiers and timestamps) are separated from model inputs. The Window_10s column is retained as a grouping key for cross-validation.

Section 08

🔀Cross-Validation Strategy

The pipeline uses Stratified Group K-Fold with 5 folds. This design simultaneously satisfies two requirements that are in tension:

RequirementWhy It MattersSolution
Group Constraint Each 10-second window contains 3 correlated sub-windows. If split across folds, the model would see overlapping signal in both train and test — an optimistic evaluation. All rows sharing the same Window_10s are always in the same fold.
Stratification With 287 unique windows across 5 folds (~57/fold), without stratification, a fold could be dominated by a single class, making metrics unstable. Each fold preserves the 60/23/17 class ratio.
Section 09

🤖Models and Hyperparameter Tuning

Four classifiers were evaluated. All use class balancing strategies to counteract the 60/23/17 label imbalance.

Support Vector Machine (SVM)

Uses an RBF (radial basis function) kernel. Probability outputs are enabled via Platt scaling. Key hyperparameters: C (regularization strength) and gamma (kernel bandwidth). Requires feature scaling.

Random Forest (RF)

A bagged ensemble of independently grown decision trees. Each tree votes on the final prediction. Key hyperparameters govern tree depth, minimum samples per split/leaf, number of trees, and feature sampling strategy. Scale-invariant; no feature scaling required.

XGBoost

A gradient-boosted tree ensemble. Unlike RF (parallel bagging), XGBoost trains trees sequentially — each tree corrects the residual errors of the previous ensemble, making it more sample-efficient on small datasets. Key hyperparameters: tree depth, learning rate, row/column subsampling, and L1/L2 regularization. Scale-invariant. Per-sample class weights are computed inside fit() via compute_sample_weight("balanced") because XGBoost's multiclass objective has no native class_weight parameter.

1D Convolutional Neural Network (CNN_1D)

A deep learning model that treats the 16-feature vector as a 1-D sequence and learns local feature interaction patterns via convolutional filters. The architecture is:

architecture Input    (16 features, 1 channel)
Conv1D(32, kernel=3, padding='same') → BatchNorm → ReLU
MaxPooling1D(2) → Dropout(0.30)
Conv1D(64, kernel=3, padding='same') → BatchNorm → ReLU
GlobalAveragePooling1D → Dropout(0.30)
Dense(128) + ReLU + Dropout(0.40)    ← FC layer 1
Dense(64)  + ReLU + Dropout(0.30)    ← FC layer 2
Dense(32)  + ReLU + Dropout(0.20)    ← FC layer 3
Dense(n_classes) + Softmax         ← FC layer 4 (output)

Training uses Adam (lr=1×10⁻³), sparse categorical cross-entropy, and per-class weights from compute_class_weight("balanced"). EarlyStopping monitors validation loss (patience=25, restore best weights); ReduceLROnPlateau halves the lr after 8 stagnant epochs. Requires feature scaling.

Tuning Approach

SVM, RF, and XGBoost were tuned using RandomizedSearchCV with 60 iterations per model, scored by macro F1. CNN hyperparameters were tuned via a dedicated random-search function in tune.py that tries 15 random draws from the CNN search space with the same StratifiedGroupKFold CV.

Section 11

⚠️Limitations

01
Missing Eustress Class
The four-quadrant stress model has no Eustress data in this session. The deployed classifier can only predict three states and will misclassify any true Eustress response.
02
Mixed Label Quality
All 519 Mixed-labeled rows come from a single 5,180-second gap forward-filled with Survey 5's label. The participant was not actively reporting Mixed stress during this window — the label is inferred, not directly measured.
03
Class Imbalance
Despite balanced class weighting, the 60/23/17 distribution limits how well the model can learn from Distress and Relaxed examples. Additional data collection would help substantially.
04
Small Dataset — especially for CNN
861 rows across three classes is a limited training set. CV variance (±0.04 on macro F1) is nontrivial. This limitation is most acute for the CNN: convolutional networks need thousands of samples to reliably learn spatial filters; with only 861 rows the CNN underfits compared to tree-based ensembles.
05
Feature Ordering for CNN
The 16 physiological features have no intrinsic spatial or temporal ordering within a single row. The 1D CNN treats adjacent features as "neighboring timesteps," but that adjacency is an artifact of engineering order, not a physical relationship. Models that treat each feature independently (RF, SVM) are architecturally better matched to this tabular input.
06
Single Participant
No claim of generalizability can be made. A model trained on one person's physiology in one context may not transfer to other individuals or environments.
Section 12

▶️How to Run the Pipeline

Stage 1: Classify Survey Responses

bash python -m src.data.classify_survey \
  --input_dir data/survey/ \
  --output_dir data/survey/

Stage 2: Align Timestamps and Merge Labels

bash python -m src.data.merge_labels \
  --features data/features/features_output_24hz.csv \
  --labels data/survey/Lighting_EMA_Main_April_6_2026_14.52_labelled.csv \
  --output data/features/features_labeled.csv

Stage 3 (optional): Re-tune Hyperparameters

bash python tune.py --data data/features/features_labeled.csv

Stage 4: Train and Evaluate

bash python train.py --data data/features/features_labeled.csv
Output files are written to results/: per-fold metrics in fold_results.csv, tuned parameters in best_params.txt, and RF feature importances in RandomForest_feature_importances.csv.
Section 13

✅Summary

The pipeline classifies three momentary stress states (Relaxed, Distress, Mixed) from wrist-worn physiological sensor data using four models. The Random Forest is the best performer; XGBoost is a strong second; the 1D CNN underperforms on this small tabular dataset as expected.

The most technically sensitive parts of the implementation are the duty-cycle timestamp correction in Stage 2 (required for correct time alignment) and the grouped cross-validation strategy (which prevents data leakage from correlated sub-windows).

The primary path to improving all models — and especially XGBoost and the CNN — is additional data: more participants, more sessions, and balanced representation across all four stress quadrants. With thousands of samples per class, XGBoost's sequential error-correction and the CNN's nonlinear capacity could both surpass the Random Forest.
