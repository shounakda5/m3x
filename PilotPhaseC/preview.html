1. Current status

After the first two weeks, we deployed a model to the rings. The deployed model is not very accurate, but we still wanted to move forward with deployment so that the rings could begin making on-device inferences.

At the same time, we also changed the data collection format in order to collect richer signals for future model improvement.

Important note: The currently deployed model should be viewed as a practical first deployment, not as the final model. The main value right now is that it allows us to continue collecting field data while also testing updated acquisition strategies.

2. What changed in the ring data collection format?

Earlier format

  • Sampling frequency: ~25 Hz
  • One window: 112 rows
  • One window duration: ~4.5 seconds
  • Ring collected 1 window, made inference, then went to sleep
  • This duty cycle repeated continuously

New format

  • Sampling frequency: ~50 Hz
  • One window: 224 rows
  • One window duration: still ~4.5 seconds
  • Ring now collects 5 consecutive windows
  • Total continuous collection per burst: ~22.5 seconds
  • After those 5 windows, ring goes to sleep
Key point: We are still preserving the window concept. A window is still about 4.5 seconds long, but because the sampling frequency doubled, each window now contains 224 rows instead of 112.
Feature Old setup New setup
Sampling frequency ~25 Hz ~50 Hz
Rows per window 112 224
Window duration ~4.5 s ~4.5 s
Windows collected before sleep 1 5 consecutive windows
Continuous data duration before sleep ~4.5 s ~22.5 s

3. Why did we make this change?

A. Higher sampling frequency

We increased the sampling frequency from ~25 Hz to ~50 Hz to test whether having more samples within the same ~4.5-second window improves the model’s ability to learn useful signal features.

B. Continuous multi-window collection

We started collecting 5 consecutive windows (~22.5 seconds total) to see whether longer continuous recordings help extract additional physiological features, especially features related to heart rate variability (HRV) or other temporal dynamics.

Main motivation: The new format allows us to explore two things at once:
  • Whether higher sampling frequency alone helps
  • Whether longer continuous signal segments help

4. Modeling ideas and possible directions

Below are some ideas and suggestions from my side. These are not strict requirements, but rather potential directions that may be useful while exploring the updated dataset.

4.1 Compare old and new formats

Since the old and new datasets have different numbers of samples per window (112 vs 224), we cannot directly mix them without some preprocessing if we want to train on single windows.

Option 1: Upsample the older 112-row windows

  • Use interpolation to convert 112-row windows into 224-row windows
  • This would allow us to combine old and new data in a common format
  • Useful if we want to test whether increased sampling frequency helps model performance

In this case, the interpolated points would be estimated between adjacent original points.

Use case: This option is most straightforward when we are training and testing on a single-window basis.

4.2 Train using only the new-format data

Another option is to keep the new-format data separate and train only on the newly collected 50 Hz / 5-window continuous segments.

Possible experiments with new-format data

  • Use each window independently
  • Use all 5 windows together as one continuous segment
  • Use 2 consecutive windows together
  • Try other grouped-window combinations if helpful
Why try 2-window groups? Because 5 consecutive windows span ~22.5 seconds, motion artifact may affect part of the burst. It is possible that shorter consecutive chunks (for example, 2 windows) may preserve useful temporal information while reducing contamination from motion.

4.3 Use motion-based filtering

Motion artifact will likely be more important in the continuous 5-window format, because it is less likely that the participant kept their hand perfectly still for the full ~22.5 seconds.

Suggested motion metric

Instead of checking only one accelerometer axis, use a combined motion metric based on the sum of the standard deviations:

std(AccX) + std(AccY) + std(AccZ)

This should be computed per window so it reflects overall motion intensity.

Possible use:
  • Set a threshold for high-motion windows
  • Exclude heavily corrupted windows from training/testing
  • Or use the motion score as a feature or quality-control indicator

5. Data cleaning suggestions before training/testing

5.1 Remove windows where the ring was not worn

In some cases, participants likely left the ring on a desk/table while stepping away (for example, restroom breaks). Those periods should ideally be excluded before model training.

Suggested criterion

  • If the accelerometer standard deviation is extremely low or close to zero
  • And the signal pattern suggests the ring is stationary on a surface
  • Then exclude those windows from training/testing
Important: This should ideally have been handled during labeling, but it was not applied there. So this filtering will need to be done as a preprocessing step before training/testing.

5.2 Apply label recency weighting

Since the continuous labeled file includes all labeled windows, covering the 0–5 min, 5–30 min, and 30–60 min periods, we can assign different weights to reflect likely label relevance.

EMA period Example weight Rationale
0–5 min 1.00 Most recent, likely most representative
5–30 min 0.75 Still relevant, but somewhat less immediate
30–60 min 0.50 Least recent, potentially lower confidence
These weights are just an example and can be tuned experimentally.

6. Concern: the model may be learning “day effects” rather than physiology

One concern is that the model may be learning differences between days rather than learning the underlying physiological signal.

For example, day-specific factors such as:

  • Baseline optical intensity
  • Temperature
  • Humidity
  • How the ring was placed on the finger that day

may make it easier for the model to identify the day/session rather than the actual stress-related physiology.

Observation: When temperature or humidity are removed, the model sometimes appears to generalize better. This suggests those channels may be helping the model learn day/session identity rather than stress state.
Suggested experiments:
  • Train with and without temperature
  • Train with and without humidity
  • Compare performance and generalization behavior

7. Feature engineering ideas

7.1 Use AC/DC-style optical features

For optical channels (LED1, LED2, LED3), one option is to reduce baseline dependence by using an AC/DC-style representation.

Possible direction

  • Compute AC component of each LED window
  • Compute DC component (mean/baseline) of each LED window
  • Use AC/DC or related normalized features

This may be more robust than directly using absolute LED means, since mean values can strongly reflect day-to-day baseline changes.

7.2 Reconsider current difference features

In the current feature set, we use differences such as:

  • LED3 - LED1
  • LED3 - LED2

One possible idea is to remove these difference features and instead replace them with normalized features such as AC/DC-derived features for each LED.

Possible feature combinations to compare:
  • Current feature set
  • Current feature set without temperature/humidity
  • Current feature set without LED difference features
  • LED AC/DC-based features instead of raw mean-based LED features

8. Practical modeling roadmap (suggested)

Step 1: Clean the continuous labeled data by removing obvious non-wear / table-placement windows.
Step 2: Compute a motion score using std(AccX) + std(AccY) + std(AccZ) and test whether filtering high-motion windows improves performance.
Step 3: Compare old-format vs new-format single-window training by upsampling the older 112-row windows to 224 rows.
Step 4: Separately test training only on the new-format data.
Step 5: Compare 1-window, 2-window, and 5-window grouping strategies.
Step 6: Test label recency weighting (0–5, 5–30, 30–60 min).
Step 7: Run ablation experiments with/without temperature and humidity.
Step 8: Explore AC/DC-based optical features and compare them with the current feature set.

9. Summary for the team

  • We will deploy models for Ring 3 and Ring 4 by tomorrow for week 4 inference.
  • The current deployed model is not highly accurate, but deployment is still useful for continued field operation.
  • The data collection format has changed:
    • Sampling frequency increased from ~25 Hz to ~50 Hz
    • Rows per window increased from 112 to 224
    • Instead of collecting one window before sleeping, the ring now collects 5 consecutive windows (~22.5 s) before sleeping
  • This change was made to study both higher sampling frequency and longer continuous signal acquisition.
  • There are multiple modeling directions worth testing, including interpolation-based alignment, motion filtering, recency weighting, feature ablation, and AC/DC-style features.
  • Non-wear or table-placement data should be removed before training/testing.
Main takeaway: The new data format gives us more flexibility to test whether richer temporal information and higher sampling density can improve inference performance, but it also introduces additional preprocessing and data-quality considerations.
