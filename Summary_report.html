M3X Ring: Machine Learning and Arduino Deployment Summary

M3X will use a wearable ring data stream with three LED channels, temperature sensing, and 3-axis accelerometer signals to classify participant state into four stress-related classes. The goal is to train and compare four ML models, then deploy the best-performing model path on the ring MCU for real-time classification.

Project: M3X Input: N × 8 raw sensor window Classes: Relax / Eustress / Distress / Eustress+Distress Models: NN, SVM, RFC, XGBoost Target: Arduino-compatible classifier

1. Project Objective

The M3X project will follow a workflow similar to the previous ODA ring ML pipeline, but the sensor input format and classification goal will be updated. The ring will provide a raw multi-channel sensor stream. We will segment the stream into optimized windows and use those windows to classify the current state as relax, eustress, distress, or eustress+distress.

The main model candidate is a neural network because it can learn directly from raw time-series windows. In parallel, we will also test SVM, Random Forest Classifier, and XGBoost using engineered physiological and motion features.

2. Data Stream and Classification Target

Raw sensor channels for neural network

  • LED1 raw signal
  • LED2 raw signal
  • LED3 raw signal
  • Temperature sensor data
  • Accelerometer X-axis: AccX
  • Accelerometer Y-axis: AccY
  • Accelerometer Z-axis: AccZ
  • Final firmware-defined sensor channel, giving 8 model input channels total
NN input shape: each inference window will be formatted as N × 8, where N is the optimized number of time samples in one window.

Four output classes

  • Relax: baseline or low-stress state
  • Eustress: positive/engaged stress response
  • Distress: negative stress response
  • Eustress + Distress: mixed or combined stress condition
Model output: a 4-class probability vector. The final predicted class is the class with the highest probability.

4. Neural Network Route: Raw Time-Series Classification

The neural-network route will directly use raw windowed sensor data. This is the closest continuation of the previous ODA workflow, but the input shape will be updated to support the new M3X ring data stream.

Input and preprocessing

  • Use each window as an N × 8 raw input matrix.
  • Normalize each channel using statistics calculated from the training set.
  • Save the normalization mean and standard deviation for MCU-side inference.
  • Optimize N by testing different inference-window lengths.

Output and evaluation

  • Final layer: Dense(4, activation='softmax').
  • Classes: relax, eustress, distress, eustress+distress.
  • Evaluate accuracy, confusion matrix, class-wise precision/recall, latency, and memory.
  • Export the final model as .tflite and .h.

5. Feature-Based Route: SVM, RFC, and XGBoost

For SVM, Random Forest Classifier, and XGBoost, we will not train directly on raw samples. Instead, each window will first be converted into a feature vector. The same feature vector can then be used to train and compare all three classical ML models.

Feature group Features Purpose
LED1 pulse features PA1, PA_STD_LED1, PA_RMSSD_LED1, PA_CV_LED1, mean_LED1 Captures LED1 pulse amplitude and pulse-amplitude variability.
LED2 pulse and heart-rate features PA2, PA_STD_LED2, PA_RMSSD_LED2, PA_CV_LED2, mean_LED2, HR_LED2, SDNN_LED2, RMSSD_LED2 Uses LED2 as the heart-rate and HRV channel. HRV features are extracted only from LED2.
LED3 intensity feature LED3_mean Adds the new M3X optical channel as an additional baseline/intensity feature.
Raw LED pairwise differences LED1_LED2_Raw_Mean_Diff, LED1_LED2_Raw_Mean_AbsDiff, LED3_LED1_Raw_Mean_Diff, LED3_LED1_Raw_Mean_AbsDiff, LED3_LED2_Raw_Mean_Diff, LED3_LED2_Raw_Mean_AbsDiff Captures relative optical response differences between LED channels.
Pulse-amplitude comparison PA1_PA2_mean_diff, PA1_PA2_AbsDiff Compares pulse amplitude behavior between LED1 and LED2.
Temperature mean_temperature Tracks average temperature during the inference window.
Motion AccX_STD, AccY_STD, AccZ_STD, Acc_Total_STD Quantifies motion artifacts and total movement during the window. Acc_Total_STD = AccX_STD + AccY_STD + AccZ_STD.

6. Model Training and Optimization Plan

Prepare data Clean collected M3X recordings, align labels, and segment the stream into candidate inference windows.
Train NN Train the neural network using raw N × 8 windows and tune architecture, window length, and normalization.
Extract features Generate one feature vector per window for SVM, RFC, and XGBoost.
Compare models Compare all four models using accuracy, confusion matrix, class balance, latency, and embedded memory needs.
Deploy Export the selected model and test the Arduino-compatible classifier on the ring MCU.

7. Ring MCU Real-Time Inference Concept

On-device inference loop

  • Continuously read the M3X ring sensor stream.
  • Accumulate a complete optimized inference window.
  • Apply the same preprocessing and normalization used during training.
  • Run the Arduino-compatible classifier.
  • Report the predicted class and confidence score.

Temporary buffering

If the optimized window becomes long, the available ring sensor memory can be used as a temporary buffer. The final implementation should check how much data can be safely stored before inference without exceeding RAM, processing-time, or power constraints.

9. One-Paragraph Summary for Lab Meeting

M3X will extend the previous ring-based ML workflow by adding a third LED channel and updating the classification target to four classes: relax, eustress, distress, and eustress+distress. The neural network route will use raw N × 8 time-series windows, while SVM, RFC, and XGBoost will use engineered features from LED pulse amplitude, pulse-amplitude variability, LED2-only heart-rate/HRV, LED channel differences, temperature, and accelerometer motion.
